# InterviewCopilot M7 — Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The React web app covering the full student journey: Google sign-in → onboarding chat + resume upload → dashboard with tracks → track detail with Interview Brief → live text interview → visual feedback report with progression.

**Architecture:** Vite + React 19 + TypeScript + Tailwind v4 + React Router + TanStack Query, in `frontend/`. The API client (`lib/api.ts`) uses `credentials: "include"` (httpOnly cookie auth). Auth context bootstraps via `GET /auth/me` (401 → sign-in screen). Long LLM operations (brief authoring, interview turns, report generation) get explicit loading states. Two small backend changes land with this milestone: CORSMiddleware for the frontend origin, and the OAuth callback redirecting to `frontend_url` instead of the inline HTML page.

**Tech Stack:** Vite 6, React 19, TS, Tailwind v4 (@tailwindcss/vite), React Router 7, TanStack Query 5, Playwright (smoke, mocked API).

**Spec:** `docs/superpowers/specs/2026-11-02-interviewcopilot-v1-build-design.md` (M7 row of §14 + §11 screens)

## Tasks

### Task 1: Backend CORS + callback redirect, Vite scaffold, app shell

- Backend: `CORSMiddleware` (origins=[settings.frontend_url], credentials=True) in `app/main.py`; `auth.py` callback returns `RedirectResponse(settings.frontend_url)` (keep the signed-in test path via `?inline=1`? — no: tests already mock the exchange, they assert cookies on the response which survives a redirect); update auth-flow test to follow_redirects=False and expect 307 → frontend_url.
- Scaffold: `npm create vite@latest frontend -- --template react-ts`; deps: `react-router-dom @tanstack/react-query tailwindcss @tailwindcss/vite`.
- Files: `frontend/src/lib/api.ts` (typed fetch wrapper), `frontend/src/context/AuthContext.tsx` (`useAuth()` → {user, loading}; bootstrap /auth/me), `App` with router: `/` dashboard, `/onboarding`, `/tracks/:trackId`, `/tracks/:trackId/interview/:sessionId`, `/tracks/:trackId/report/:sessionId`, sign-in fallback.
- Commit: `feat(web): vite scaffold, auth context, api client, app shell`.

### Task 2: Onboarding chat + vault + resume

- `OnboardingPage`: message list (user/assistant bubbles), input box, `POST /onboarding/chat` mutation (loading indicator while the agent thinks), extracted items appear as toast/chips; sidebar with `GET /onboarding/state` vault items grouped by category; resume upload (`POST /vault/resume`, PDF only, progress state).
- Commit: `feat(web): onboarding chat with vault and resume upload`.

### Task 3: Dashboard — tracks list + create

- `DashboardPage`: track cards (`GET /tracks`, brief_version badge, track_type chip), create-track form (type select / subject / company / JD textarea — JD required for company_jd), creation shows "Interview Architect is designing your brief…" state (LLM ~30 s), navigation to detail.
- Commit: `feat(web): dashboard with track creation`.

### Task 4: Track detail + interview chat + report

- `TrackDetailPage`: brief summary, competency chips (importance-coded), question areas, preparation plan, progression banner (`strict_completed`, `guided_state` with "Guided unlocked!" state), Start Interview button → creates session → navigates to interview page.
- `InterviewPage`: chat-style turns from `GET /sessions/{id}`; answer textarea + submit (`POST /turns`); per-turn evaluation chips (coverage color); completed banner → link to report; recovery-friendly (page load refetches session).
- `ReportPage`: overview, coverage status, competency cards (level color-coded, NOT_ASSESSED greyed), strengths/improvements/recommendations sections, question-evidence accordion.
- Commit: `feat(web): track detail, interview session, feedback report`.

### Task 5: Build, smoke test, README, push

- `npm run build` green; Playwright smoke with **route interception** (mocked backend): sign-in-gated redirect, dashboard renders mocked tracks, interview flow with mocked turns. `npm run e2e`.
- README: frontend quickstart (`npm install`, `npm run dev` at :5173, `npm run e2e`).
- Live acceptance (user-driven): sign in via browser, full journey.
- Commit: `docs: frontend quickstart` + push → PR.
