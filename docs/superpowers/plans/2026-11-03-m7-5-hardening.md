# InterviewCopilot M7.5 — Hardening Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve the accepted findings from the November 3 external audit (quick-win batch) plus five gaps the audit missed, without changing any product behavior. Design-level items (token revocation, rate limiting, CORS narrowing) stay deferred to M8.

**Architecture:** Evaluations become part of the domain (persisted on `session_turns` at grading time), so the frontend drops its fragile parallel state. NATS gains durable storage and a reused connection. Blocking I/O moves off the event loop. Secrets gain production validators. Frontend gets strict TS, defensive API handling, and bounded polling.

**Spec:** audit of 2026-11-03; deviations recorded where noted.

## Global Constraints

- Same as M1–M7. Tests hit `interviewcopilot_test` (migrate BOTH DBs). Behavior-preserving except where the audit flagged bugs.

### Task 1: Secrets hardening (audit #1, #4)

**Files:** `backend/app/core/config.py`, `backend/app/main.py`, `backend/tests/test_settings.py`

- Add `session_secret: str = "dev-session-secret-change-me"` to Settings; `main.py` uses it for `SessionMiddleware`.
- Add a pydantic `model_validator(mode="after")`: when `app_env != "local"`, both `jwt_secret` and `session_secret` must be set and not equal to their dev defaults (and ≥32 chars) or Settings raises.
- Tests: prod env + default secret → ValidationError; prod env + strong secrets → OK; local env unchanged.
- Commit: `fix(backend): production secret validation, separate session secret`.

### Task 2: Persist turn evaluations (audit #2 — the big one)

**Files:** `backend/app/models/interview.py` (+ migration, both DBs), `backend/app/services/interview_service.py`, `frontend/src/lib/api.ts`, `frontend/src/pages/InterviewPage.tsx`, `backend/tests/test_interview.py`

- `SessionTurn` gains `evaluation_coverage: str | None`, `evaluation_strengths: JSONB | None`, `evaluation_gaps: JSONB | None`, `interviewer_notes: Text | None` (the previously discarded `notes_for_report`).
- `submit_answer` writes the evaluation onto the *answered* turn before deciding the next move.
- `GET /sessions/{id}` returns evaluations with their turns; `_turn_dict_full` includes them.
- Frontend: `Turn` type gains the evaluation fields; `InterviewPage` deletes the local `evaluations` state and renders each evaluation attached to its own turn (fixes the alignment bug too). Refresh now preserves all feedback.
- Tests: after answering, `GET /sessions/{id}` shows `turns[0].evaluation.coverage == "partial"`.
- Commit: `feat: persist interview turn evaluations (fixes refresh data loss)`.

### Task 3: Infra — NATS durability + connection reuse + Mongo index (audit #7, #8, #9)

**Files:** `infra/docker-compose.yml`, `backend/app/main.py`, `backend/app/services/events.py`, `backend/app/services/interview_service.py`

- NATS service: `command: ["-js", "-sd", "/data", "-m", "8222"]` + `nats_data:/data` volume.
- Lifespan connects a shared NATS client into `app.state.nats` (suppressed on failure — API boots without NATS); `publish_feedback_job(..., nc=None)` uses the injected client when given, else falls back to connect-per-call; `_dispatch_feedback` threads it from the request context.
- Lifespan also creates the Mongo index `user_id` (unique) on `onboarding_conversations` (suppressed).
- Also pin the SeaweedFS image by digest (audit low-item 5).
- Commit: `feat(infra): nats jetstream volume + reused client; mongo user index; pin seaweedfs`.

### Task 4: Async I/O + API hygiene (audit #6, #10; low-items 1, 2)

**Files:** `backend/app/services/resume_service.py`, `backend/app/api/v1/vault.py` + `onboarding.py` + `tracks.py`, `backend/app/agents/onboarding.py`, `backend/app/services/interview_service.py`

- `resume_service`: `asyncio.to_thread` for `put_object`, `extract_pdf_text`, and route-level `ensure_bucket`.
- `_count_turns` → SQL `func.count`; `_latest_turn` → `order_by desc limit 1`.
- `ITEM_CATEGORIES` set constant in `agents/onboarding.py`; `vault.py` route checks against it (drops pydantic-internals reflection).
- Bound payloads: `ChatRequest.message` and `CreateTrack.jd_text` get `max_length=20000`.
- Commit: `fix(backend): off-loop blocking io, sql count/latest, payload bounds, category constant`.

### Task 5: Frontend robustness (audit #3, #11, #12; low-items 3, 4)

**Files:** `frontend/src/lib/api.ts`, `frontend/src/pages/ReportPage.tsx`, `frontend/src/App.tsx`, `frontend/src/lib/ui.ts`, `frontend/tsconfig.app.json`

- `api.ts`: return `null` on 204 / zero-length bodies.
- `ReportPage`: poll only while `ApiError.status === 404`, capped at 24 polls (2 min) via a ref; other errors render as final states.
- `App.tsx`: catch-all `*` route with a friendly NotFound block.
- `src/lib/ui.ts`: shared `COVERAGE_STYLE` + `LEVEL_STYLE`; Interview/Report pages import them.
- `tsconfig.app.json`: `"strict": true`; fix whatever type errors surface; `npm run build` must stay green; Playwright suite must stay green (adjust mocked turns to include evaluation fields if the page expects them).
- Commit: `fix(web): strict ts, 204-safe api client, bounded report polling, shared styles, 404 route`.
