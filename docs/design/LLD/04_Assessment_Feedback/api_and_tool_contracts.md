# API and Tool Contracts

## 1. Public API Endpoints

Coordinate with Member 1 (API conventions) and Member 3 (session endpoints).

| Method | Endpoint | Purpose |
|--------|----------|---------|
| `GET` | `/api/v1/sessions/{session_id}/feedback-status` | Retrieve feedback job/report status |
| `GET` | `/api/v1/sessions/{session_id}/feedback` | Retrieve completed report for the owner |
| `GET` | `/api/v1/tracks/{track_id}/progression` | Retrieve current Strict/Guided eligibility and attempt count |

All requests authorized using authenticated user context from Member 1's auth middleware.

### 1.1 Feedback Status Response

```json
{
  "session_id": "session_uuid",
  "session_status": "FEEDBACK_PROCESSING",
  "feedback_status": "PROCESSING",
  "retryable": false,
  "updated_at": "2026-11-02T10:45:00Z"
}
```

### 1.2 Feedback Report Response

```json
{
  "session_id": "session_uuid",
  "feedback_status": "COMPLETED",
  "report": {
    "report_id": "report_uuid",
    "summary": {},
    "question_assessments": [],
    "competency_assessments": [],
    "strengths": [],
    "improvement_areas": [],
    "unassessed_topics": [],
    "recommendations": []
  }
}
```

The backend may paginate detailed question assessments for larger sessions.

## 2. Internal Tool Contracts

The HLD identifies these Feedback Agent tools (to be specified with Member 1's Agent Tool Layer template):

### 2.1 LLM-Callable Tools (via Agent Tool Layer)

| Tool | Purpose | Input | Output |
|------|---------|-------|--------|
| `get_completed_session` | Load session metadata | `{session_id}` | Session metadata |
| `get_session_transcript` | Load ordered transcript turns | `{session_id}` | Turn array |
| `get_candidate_snapshot` | Load profile snapshot | `{profile_version_id}` | Candidate snapshot |
| `get_interview_brief` | Load brief version | `{interview_brief_version_id}` | Interview Brief |
| `get_session_artifacts` | Load session artifacts | `{session_id}` | Artifact list |
| `save_feedback_report` | Persist detailed report | Report object | `{report_id, report_version}` |

### 2.2 Backend Service Operations (Not LLM-Callable)

| Operation | Purpose | Input | Output |
|-----------|---------|-------|--------|
| `save_assessment_summary` | Persist structured summary | Summary object | `{summary_id}` |
| `apply_track_memory_update` | Idempotent memory merge | `{track_id, session_id, memory_delta}` | Update receipt |
| `apply_question_history_update` | Idempotent history merge | `{track_id, session_id, questions[]}` | Update receipt |
| `evaluate_track_progression` | Run progression policy | `{track_id}` | Eligibility decision |
| `finalize_session_completion` | Mark session COMPLETED | `{session_id}` | Confirmation |

These are trusted backend service operations. Keep final authorization, persistence and progression logic outside the LLM's control.

### 2.3 Common Tool Contract Requirements (per Member 1)

Every tool must define:
- Tool name and owning service.
- Allowed agent role.
- Typed input and output.
- Ownership checks.
- State preconditions.
- Idempotency key.
- Read/write side effects.
- Stable error codes.
- Audit requirements.

The worker supplies trusted user/job/session context. Never accept an arbitrary user ID generated by the model as authorization.
